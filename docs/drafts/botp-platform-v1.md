# BOTP 下推反写平台 V1 需求草案

## 1. 建设目标

在 Matrix 中建设独立的 BOTP（Business Object Transformation Platform）能力，为内部单据和外部业务系统提供可配置的单据转换、目标单创建、上下游关联、反写、重试与追踪能力。

## 2. V1 范围

- 单据类型元数据模型。
- 转换规则与不可变规则版本。
- 单头字段映射和一对一分录映射。
- 字段来源支持：源字段、常量、执行上下文。
- 转换预览，不创建真实目标单。
- 同步执行接口和请求幂等。
- 单据适配器 SPI，业务模块不得由 BOTP 直接写表。
- 执行状态查询。
- 上下游关系、反写与 Outbox 的数据库交付设计。
- 提供可运行的内存演示适配器，用于验证引擎流程。

## 3. V1 暂不实现

- 多源单合并、一单拆多单。
- 任意脚本、SQL、Groovy、JavaScript 或 SpEL 公式。
- RabbitMQ 实际投递与外部回调。
- 真实应付单到付款申请单适配器。
- 生产级数据库持久化实现。

## 4. 核心约束

1. BOTP 不直接操作业务单据表，只能调用单据适配器。
2. 已发布规则不可覆盖修改，只能发布新版本。
3. 执行任务必须记录规则版本。
4. 外部调用以租户、来源系统、请求号作为幂等维度。
5. 目标创建成功后，反写失败只能重试反写，不能再次创建目标单。
6. 反写累计值优先根据有效关联关系重算，避免重复加减。

## 5. 第一条真实业务链建议

应付单 → 付款申请单：支持按分录部分金额下推，反写已下推金额、剩余金额和下推状态，并在目标单作废时重新计算。

## 6. 验收标准

- 能通过 API 查询规则。
- 能提交源单引用并预览目标草稿。
- 能执行演示规则并生成目标单结果。
- 相同幂等请求重复调用返回相同执行结果。
- 未注册适配器、规则不存在、必填映射缺失时返回明确错误。
- Maven 模块结构和数据库命名符合 Matrix 规范。
